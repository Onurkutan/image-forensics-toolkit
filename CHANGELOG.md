## [Unreleased]

### Added

- Project skeleton, core types, CLI stub, CI
- Literature surveys on AI-generated image detection, manipulation localization, and classical forensic signals (docs/research/)
- Development roadmap (docs/ROADMAP.md)
- `ForensicImage` input type carrying original bytes
- metadata signal (EXIF, editor and AI-generator markers, thumbnail consistency, JPEG quality estimate)
- ELA signal with heatmap
- CLI: per-signal cards, `--json`, `--save-heatmaps`, `--detector`
- metadata signal: `jpeg_quant_standard` / `jpeg_quant_quality_exact`, an exact IJG-standard-table classification of the JPEG's luma+chroma quantization tables (complementing the existing quality estimate)
- `c2pa` signal: C2PA manifest verification via the optional `c2pa-python` extra (`pip install imgforensics[provenance]`), lazily imported so the base install is unaffected
- `sd_watermark` signal: decodes the Stable Diffusion `dwtDct` invisible watermark via a vendored pure numpy/opencv/PyWavelets codec (`src/imgforensics/signals/_vendor/dwtdct.py`, from `ShieldMnt/invisible-watermark`), checked against the SDXL 48-bit and CompVis Stable Diffusion v1 136-bit reference payloads
- `copy_move` signal: block-matching copy-move (duplicated-region) detector with a matched-region heatmap, using overlapping quantized zig-zag-DCT block features sorted for near-neighbour matching and a shift-vote with a periodic-texture guard
- `jpeg_ghost` signal: Farid's JPEG-ghost recompression-quality mismatch, with a splice-localization heatmap
- `double_jpeg` signal: JPEG 8x8 blocking-grid offset (crop/composite detection) and aligned double-quantization periodicity, both pixel-domain checks with no DCT-coefficient library dependency
- shared test fixture `tests/conftest.py::natural_like_image`, reused by the copy-move, JPEG-ghost and double-JPEG test suites
- `imgforensics.data.manifest`: `Manifest`/`ManifestEntry`/`ManifestMeta` (pydantic), JSON-Lines save/load, `summary()`, and `build_manifest()` to walk a labeled image tree (sha256, resolution, format, JPEG quality via the metadata signal's quality estimator) with a `label_from_parent_folder` helper for `real`/`fake`-style folder layouts
- `imgforensics.data.registry`: `DatasetInfo` and a packaged `datasets.yaml` cataloguing 24 datasets from the AI-generated-image-detection and manipulation-localization literature surveys, each with license, access, and a `commercial_ok` flag (`None` when unverified); `load_registry()`, `get_dataset()`, `registry_table_markdown()`
- `imgforensics.data.audit`: `audit_manifest()` bias audit comparing a manifest's real/fake halves by format, resolution, JPEG-quality, and aspect-ratio distribution (Jensen-Shannon distance) plus within- and across-label duplicate detection; `AuditReport.to_markdown()`; strict mode raises `BiasError`
- `imgforensics.eval.metrics`: pure-numpy image-level metrics (`roc_auc`, `average_precision`, accuracy/balanced-accuracy/FPR/TPR at a threshold, `best_threshold`, `expected_calibration_error`, `brier_score`) and pixel-level metrics (`pixel_f1`, `pixel_best_f1`, `pixel_ap`, `pixel_iou`), bundled as `ImageMetrics`/`PixelMetrics`
- CLI: `imgforensics datasets list` / `datasets show NAME`, `imgforensics audit MANIFEST [--strict]`, `imgforensics manifest build ROOT --dataset NAME --out PATH [--license] [--commercial-ok/--no-commercial-ok]`
- `PyYAML` runtime dependency, used to load the packaged `datasets.yaml` registry
- `imgforensics.eval.robustness`: `Perturbation`/`RobustnessSuite` (pydantic), a deterministic robustness suite (JPEG/WEBP re-encoding, resize, a resize round-trip, center crop, Gaussian noise, and a "social" resize+JPEG+metadata-strip pipeline) seeded from `sha256(image bytes + perturbation name)` so every random operation is byte-identical across runs; packaged default suite `eval/robustness_default.yaml` (clean; `jpeg_q95`..`jpeg_q50`; `webp_q80`; three resize scales; a round-trip; a center crop; two noise levels; `social_1080_q80`)
- `imgforensics.eval.preprocess`: `center_crop`/`random_crops`/`grid_crops` (reflection-padded native-resolution crops, never a resize) and `AugmentationConfig`/`augment()`, the training-time counterpart of the robustness suite (randomized JPEG/WEBP/blur/downscale-upscale/noise/cutout, each applied with probability `p`), explicitly documented as unsafe to use at evaluation time
- `imgforensics.eval.baselines`: trivial detectors kept out of the global registry so `imgforensics analyze` never runs them -- `ConstantDetector` (`constant_real`/`constant_fake`), `RandomDetector` (`random`, seeded per image), `SignalsMeanDetector` (`signals_mean`, mean of every registered signal); `baseline_detectors()`
- `imgforensics.eval.runner`: `BenchmarkConfig`/`BenchmarkResult`/`run_benchmark()`, a benchmark runner that evaluates registered detectors (and, optionally, the baselines) over a manifest at every robustness level, tunes each detector's threshold on the val split's clean level (falling back to in-sample tuning with a "threshold tuned in-sample" caveat when no val split exists), and reports image metrics, a per-level robustness table, per-generator/source AUC, pixel metrics (when masks are present), and timing as Markdown; `save_json()`/`load_json()` round-trip the underlying records
- CLI: `imgforensics benchmark MANIFEST [--detector NAME ...] [--all-signals] [--baselines] [--robustness default|PATH|none] [--limit N] [--root DIR] [--out results.json] [--report report.md]`
- `imgforensics.data.acquire`: `AcquireStep`/`AcquireRecipe` (pydantic) and a packaged `acquire.yaml` of license-gated download recipes for 10 registry datasets (Community Forensics, Synthbuster, COCO, CocoGlide, CASIA v2.0, TGIF, ITW-SM, WildRF, Chameleon, MIML); `fetch()` prints the registry's license/`commercial_ok`/homepage, refuses to download without `accept_license=True` (dry runs excepted), writes a `LICENSE_ACCEPTED.txt`, and runs `http` (streaming download with `.part`-file HTTP-Range resume, optional sha256 verification, zip/tar unpack), `hf` (`huggingface_hub.snapshot_download`, lazily imported), `gdrive` (`gdown.download`, lazily imported) and `manual` (prints instructions, never handles credentials) steps; `FetchReport`/`StepReport`; `get_recipe()`/`load_acquire_recipes()`
- `imgforensics.data.acquire`: an `hf` step's optional `max_files` bounds the download to the first N sorted files matching `allow_patterns` (`huggingface_hub.list_repo_files` + `hf_hub_download`, both lazily imported) instead of pulling the whole repository via `snapshot_download`; the packaged "Community Forensics" recipe now defaults to `max_files: 8` (a few GB of Parquet shards, not the ~260 GB `-Small` repository) with a `full` variant for the unbounded download
- `imgforensics.data.acquire`: `_unpack` rejects a zip/tar member whose path is absolute or escapes the destination directory (`..` traversal), raising `ValueError` before extracting anything, on every Python version -- the 3.12+ `tarfile` `filter="data"` extraction filter is kept as an additional layer, not a replacement
- `imgforensics.data.layouts`: `Layout` (pydantic) and a packaged `layouts.yaml` of on-disk folder-shape descriptions (real/fake globs with `**` support, generator/split extraction by parent folder or regex, a mask-path template) for Synthbuster, COCO, CASIA v2.0, TGIF, ITW-SM, WildRF, and the materialized shape of Community Forensics; `prepare()` builds, saves and audits a manifest from a downloaded folder using its layout, falling back to `label_from_parent_folder` when no layout is registered; `materialize_parquet()` converts Community Forensics Small's Parquet shards into a real/fake folder tree (requires the optional `pyarrow`, not an imgforensics dependency; prints instructions when unavailable); `get_layout()`/`load_layouts()`
- `imgforensics.data.manifest`: `sample()` (deterministic, proportional stratified subsampling via the largest-remainder method, seeded per stratum, never exceeds a stratum's available count) and `merge()` (concatenates manifests, keeping root-relative paths when every input shares a root or rewriting to absolute paths with a note otherwise)
- CLI: `imgforensics datasets fetch NAME --dest DIR [--variant V] [--accept-license] [--dry-run]`, `imgforensics datasets recipe NAME`, `imgforensics datasets prepare NAME --src DIR --out manifest.jsonl [--strict-audit]`, `imgforensics manifest sample IN --n N --out OUT [--seed S] [--stratify label,generator]`, `imgforensics manifest merge A B ... --out OUT`
- optional `data` extra (`huggingface_hub`, `gdown`) for `imgforensics.data.acquire`'s `hf`/`gdrive` download methods; the base package imports without it
- `imgforensics.detectors.backbones`: `BackboneSpec` (pydantic) and a `BACKBONES` registry of two frozen ViT feature spaces -- `dinov2_vitb14` (`vit_base_patch14_dinov2.lvd142m`, Apache-2.0) and `clip_vitl14` (`vit_large_patch14_clip_224.openai`, MIT); `load_backbone()` loads them through timm in eval mode with gradients disabled and builds them at the spec's `input_size` so timm resamples the pretrained position embeddings (DINOv2's timm entry defaults to 518 px and asserts on any other input; at 224 px its patch-14 grid is 16x16) (weights downloaded from the Hugging Face Hub on first use, cached in `IMGFORENSICS_WEIGHTS_DIR` when set, never committed), `normalization_for()` reads the mean/std from the weights' own timm `pretrained_cfg` instead of hardcoding them, and `extract()` returns the CLS token of each selected block plus the pooled output as a `(batch, len(layers) + 1, dim)` tensor via timm's `forward_intermediates(..., return_prefix_tokens=True, norm=True, output_fmt="NLC")`, under float16 autocast on CUDA
- `imgforensics.detectors.crops`: `CropPolicy` (pydantic: size, `center`/`grid`/`random` mode, max crops, seed, reflection padding) and `crops_for()` -- native-resolution crops only, never a resize; `grid` takes the tiles closest to the image center, `random` derives its seed from `sha256(image bytes + policy seed)` like the robustness suite so crops are reproducible per image; `to_array()`/`to_tensor()` produce the normalized `(N, 3, H, W)` batch (`to_array` is pure numpy, so the crop policy works without the `ml` extra)
- `imgforensics.detectors.features`: `FeatureExtractor` (lazy backbone load, crops batched across images, `features_for_image()` -> `(n_crops, n_layers, dim)`, `features_for_paths()` streaming in input order) and `FeatureCache`, one `.npz` per (image sha256, backbone, crop-policy hash) holding `features` (float16 on disk, float32 in memory), `layers`, `crop_policy`, `backbone` and `created`, sharded by sha256 prefix, plus an informational `index.json`
- `imgforensics.detectors.is_ml_available()`: reports whether the optional `ml` extra is installed; the `detectors` package and the CLI import cleanly without torch/timm (every torch import sits inside the function that needs it), pinned by a test that imports them in a subprocess where torch and timm are unimportable
- CLI: `imgforensics features extract MANIFEST [--cache-dir DIR] [--backbone NAME] [--crop-mode center|grid|random] [--max-crops N] [--limit N] [--device auto|cpu|cuda]` (prints device, cache hits, feature shape, throughput in images/s and cache size) and `imgforensics features info [--cache-dir DIR]` (cached images per backbone); both print an install hint and exit 1 when the `ml` extra is missing
- optional `ml` extra (`torch`, `torchvision`, `timm`, `safetensors`) and a `ml` pytest marker; a separate CI job installs the extra from the CPU wheel index and runs `pytest -m ml`, leaving the default job torch-free
- `imgforensics.detectors.head`: `MultiLayerHead`, the trainable head over cached frozen-backbone features -- per-layer LayerNorm + Linear projection (separate weights per depth), learned layer-importance logits (softmax, or a fixed uniform mean as the ablation), and a GELU/dropout MLP to one logit per crop (1,058,054 parameters at the DINOv2 ViT-B/14 shape of 5 x 768); `HeadOptions`/`HeadConfig` (the shape is inferred from the cached features, never configured), `layer_weights()` for reporting which depths a trained head leaned on, `aggregate_crops()` (mean or max over crop *probabilities*, not logits), and the checkpoint schema `CheckpointMeta`/`Calibration`/`ManifestRef`/`ValMetrics`
- `imgforensics.detectors.train`: `TrainConfig` (YAML-loadable) and `train_head()` -- extracts anything missing from the feature cache so `train` can run without a separate `features extract`, loads every cached view as crop-level samples carrying their image's label, trains with AdamW + a cosine schedule and BCEWithLogits (optional label smoothing and class-balanced sampling, deterministic from one seed, no mixed precision), evaluates image-level AUC and balanced accuracy on the validation manifest's un-augmented view-0 features after every epoch, keeps the best-AUC epoch and early-stops, then fits a temperature and bias by LBFGS on the image-level NLL; `TrainReport`/`EpochRecord`
- post-hoc calibration is clamped and *verified*: a fitted temperature/bias is applied only if it does not increase the expected calibration error on the validation split, so a run that cannot improve on raw logits records the identity calibration and an unchanged ECE rather than a silent regression
- a trained head writes a self-describing checkpoint directory: `head.safetensors` (weights), `head.json` (package version, backbone and its layer indices, crop policy, augmentation config path and hash, views, head config, calibration, best epoch, validation AUC / balanced accuracy at 0.5 and at the tuned threshold / ECE before and after, each manifest's name, entry count and file sha256, created timestamp, and the `commercial_ok` flag ANDed across the training manifests plus their license strings) and `training_log.jsonl` (one line per epoch)
- `imgforensics.detectors.learned`: `LearnedDetector`, registered as `dinov2_head`, so a trained head runs inside `imgforensics analyze` and the benchmark runner next to the classical signals -- crops per the checkpoint's own crop policy, one forward pass through a lazily built, instance-shared `FeatureExtractor`, calibrated per-crop probabilities averaged into the image score, and a heatmap of the image's shape with each crop's probability painted over the region it was cut from (overlaps averaged, for `random` mode). Checkpoint location: the constructor argument, else `IMGFORENSICS_HEAD_DIR`, else `weights/dinov2_head/`; with no checkpoint the detector abstains (score 0.5, `uncertain`, and a `reason` naming the directory and the command to train one) instead of failing the run. Registered only when the `ml` extra is installed, and the module imports no torch at module scope, so `analyze` on a torch-free machine is unchanged and startup cost is unaffected where it is installed
- `imgforensics.detectors.features`: augmented multi-view feature caching -- `FeatureExtractor(augment=..., views=K)` produces view 0 (the image untouched) plus K-1 augmented views per image, each seeded from `sha256(image bytes + "view<k>" + policy.seed)` so a view is reproducible from the image alone; `CacheKey` gains `augment_hash` and `view`, and `features_for_paths()` now yields `(path, view, features)`. View 0 keeps the pre-augmentation file name and is shared with a plain extraction (it is un-augmented by construction), so existing caches stay valid and identical pixels are never cached twice
- `imgforensics.detectors.crops`: `crop_boxes()` and `CropBox` -- where `crops_for()` took each crop from, in the source image's own coordinates and clipped to it, which is what lets a per-crop score be painted onto an image-shaped heatmap. Both read their placements from one private helper, so a box can never disagree with the crop it describes
- `imgforensics.eval.preprocess`: `AugmentationConfig.probabilities`, a per-augmentation firing rate keyed by the model's own field names (falling back to the shared `p`), because real capture pipelines do not degrade at one uniform rate; `AugmentationConfig.fingerprint()`, the cache-key hash matching `CropPolicy.fingerprint()`
- `imgforensics.signals.SIGNAL_NAMES`: the registry names of the classical signals, now that the registry can also hold the learned detector
- committed configs: `configs/augment_default.yaml` (JPEG Q30-95 p 0.7, WEBP Q40-95 p 0.3, downscale-upscale 0.5-0.9 p 0.3, blur sigma 0.3-1.2 p 0.2, noise sigma 1-6 p 0.3, cut-out 32 px p 0.2) and `configs/head_dinov2.yaml` (training defaults with placeholder manifest paths under `data/manifests/`)
- CLI: `imgforensics train head --config CONFIG.yaml [--epochs N] [--out DIR]` (prints head size, crop/image counts, best epoch, validation AUC and balanced accuracy, ECE before/after, the fitted calibration, the learned layer weights, and the training data's licenses); `imgforensics features extract` gains `--augment CONFIG.yaml` and `--views K`
- `pyarrow` runtime dependency of the optional `data` extra, used by `imgforensics.data.layouts.materialize_parquet`
- `imgforensics.data.layouts.materialize_parquet()` reworked against Community Forensics Small's confirmed dataset-server schema (`image_name`, `format`, `image_data`, `model_name`, `nsfw_flag`, `prompt`, `real_source`, `subset`, `split`, `label`, `architecture`): reads every shard one row group at a time via `pyarrow.parquet.ParquetFile.iter_batches` (never a whole shard in memory), writes each row's raw `image_data` bytes unchanged (no re-encoding; the file extension comes from `format`), maps `label` to `real`/`fake` whether it is encoded as `0`/`1`, a bool, or a `"real"`/`"fake"` string (raising loudly on anything else), skips (and counts) `nsfw_flag` rows, is idempotent (an existing target file is skipped by name, not rewritten), and writes `<out_dir>/materialize.json` (rows read/written, skipped-by-reason, per-label and per-generator counts, formats seen) plus a sidecar `<out_dir>/attributes.jsonl` (one line per materialized image: path, `model_name`, `architecture`, `subset`, `split`, `prompt` truncated to 200 chars); returns a `MaterializeReport` instead of a bare int
- `imgforensics.data.layouts.prepare()`: when `<src_root>/attributes.jsonl` exists (written by `materialize_parquet`), its `model_name`/`split` fill each entry's `generator`/`split`, falling back to the layout- (or `label_from_parent_folder`-) derived folder value for anything the sidecar leaves unset -- preserves the exact generator name even where a folder name had to be written differently
- CLI: `imgforensics datasets materialize NAME --src DIR --out DIR [--max-rows N]`
- `imgforensics.data.manifest.split_by_group()`: splits a manifest into two group-disjoint halves (`generator` by default) -- every non-`None` group's entries land entirely in one half, either following an explicit `holdout` list or (absent one) a deterministically shuffled, largest-group-first greedy assignment targeting `val_fraction` of the grouped entries; entries with no group (typically reals) are split proportionally at random, seeded, so both halves contain reals; both returned manifests get their entries' `split` set to `"train"`/`"val"` and a `meta.notes` describing the split
- CLI: `imgforensics manifest split IN --out-train A --out-val B [--by generator] [--val-fraction 0.2] [--holdout GEN ...] [--seed 0]`, printing each side's group list
- `docs/experiments/01_dinov2_head_community_forensics.md`: a step-by-step runbook for the first `dinov2_head` real-data run (fetch, materialize, prepare/audit, generator-disjoint split, optional COCO reals, feature extraction, training, and benchmarking against both a held-out slice and ITW-SM), with disk-footprint notes and a "what to report" checklist for `docs/benchmarks/`
- `imgforensics.data.manifest.crop_entries()`: writes native-resolution square crops (never a resize) of selected manifest entries into a new image tree and manifest -- `mode="center"` (one crop) or `mode="tiles"` (every non-overlapping tile, row-major, `_t00`/`_t01`/...) -- so a class whose images run at a larger native resolution than another (e.g. 1024 px reals vs. 512 px fakes, which `imgforensics.data.audit` flags) can be cut down to match without a resize's own detectable low-pass trace; an image too small to crop passes through unchanged, and every entry outside `labels` is copied through byte-for-byte, so the output stays a complete dataset; outputs are always PNG regardless of the source format; deterministic (sorted by source path, then tile index) and idempotent (an existing output file is not rewritten); `sha256`/`width`/`height`/`format`/`jpeg_quality` are recomputed from the file actually written via the same helper `build_manifest` uses; `CropReport` (counts of cropped images, tiles written, passthrough, copied, skipped-unreadable, bytes written)
- CLI: `imgforensics manifest crop IN --out-dir DIR --out OUT --size N --mode center|tiles [--label real ...] [--min-side N]`
- `imgforensics.localization._vendor.iml_vit`: IML-ViT's model definition, vendored for inference from `SunnyHaze/IML-ViT` at commit `07dd2be0f4ea27a5c97c9fa5ffbe236733833eac` (MIT) -- a plain ViT-B/16 with windowed attention and decomposed relative position embeddings, a simple feature pyramid, and a SegFormer-style decoder head. Training-only code (the BCE and edge losses, the MAE initialization hook, the augmentation pipeline) and the `fvcore` dependency were removed rather than added; every module and parameter name is unchanged, so the released checkpoint loads with `strict=True`. Each file keeps the upstream license header and lists its own modifications; see THIRD_PARTY_NOTICES.md
- `imgforensics.localization.weights`: `WeightSpec` (pydantic) and a `WEIGHTS` registry of downloadable model weights, plus `fetch_weights()` -- the model-weights counterpart of `datasets fetch`. It prints the model's license, `commercial_ok` flag, approximate size and source, refuses to download without `accept_license=True`, reuses `imgforensics.data.acquire`'s `http`/`gdrive` helpers instead of growing a second downloader, verifies the recorded sha256 (deleting a bad download, reporting a bad file already on disk), and is idempotent: an already-present, verified file is reported as `cached` without touching the network. Files land in `$IMGFORENSICS_WEIGHTS_DIR/<name>/` or `weights/<name>/`, both gitignored -- weights are never committed. The module is torch-free, so weights can be fetched on a machine that cannot yet run them
- `imgforensics.localization.iml_vit`: `IMLViTLocalizer`, registered as `iml_vit`, the first pixel-level localizer -- inference on the released IML-ViT weights returning a float32 heatmap of the image's own shape in [0, 1]. Images at or below 1024 px are zero-padded at the bottom-right to 1024 and cropped back, following upstream's own preprocessing (ImageNet normalization applied after the padding, so the padded region reaches the model as `-mean/std`); larger images, which upstream's transform would truncate to their top-left 1024x1024 corner, are covered by overlapping 1024 px tiles at stride 768 whose overlaps are averaged -- crop and pad, never resize, and never truncate. fp16 autocast on CUDA. The image-level score is the mean of the top 1% of heatmap values, documented in the module as this project's choice because the paper and released code define no image-level rule; `details` reports `weights` (filename plus the sha256 prefix of the file actually loaded), `tiles`, `max_prob`, `mean_prob`, `area_fraction_above_0.5` and `device`. With no weights installed it abstains (0.5, `uncertain`, a `reason` naming the directory and the fetch command) instead of failing the run. Registered only when the `ml` extra is installed, and the module imports no torch at module scope
- CLI: `imgforensics weights list` (every registered model with its license, commercial flag, size and whether it is installed) and `imgforensics weights fetch NAME [--dest DIR] [--accept-license]`
- `imgforensics.data.layouts`: a packaged `layouts.yaml` entry for CocoGlide, added after inspecting the extracted archive (real/ 512 authentic COCO crops, fake/ 512 GLIDE-inpainted, mask/ 512 binary masks, plus table.csv). The archive names each mask after its *authentic* partner while the manipulated file carries a GLIDE-derived name, so image and mask share only a COCO image id; the entry's `mask_template` therefore reads a `mask_paired/` folder that one documented, idempotent pass over the archive's own table.csv creates, which attaches each mask to the manipulated image and correctly leaves authentic images without one
- `docs/benchmarks/03_cocoglide_iml_vit.md`: the first localization benchmark -- IML-ViT on all 1,024 CocoGlide images (512 authentic, 512 GLIDE-inpainted), reporting pixel F1@0.5, best-F1, AP and IoU alongside the image-level AUC, with wall time and peak VRAM
- `BenchmarkConfig.workers` / CLI `imgforensics benchmark ... --workers N`: evaluates the classical signal detectors (`imgforensics.signals.SIGNAL_NAMES`, plus the `constant_real`/`constant_fake`/`random` baselines when selected) in a `concurrent.futures.ProcessPoolExecutor`, one task per (entry, robustness level) pair, so they no longer serialize with a slower GPU-based detector in the same run; every other detector (a learned detector such as `dinov2_head`, and `signals_mean`, which needs every signal itself) keeps running in the main process. `imgforensics.eval.workers` holds the module-level worker function Windows' `spawn` start method requires (each worker process builds and caches its own detector instances by name); worker records are merged back and sorted by `(entry order, level order, detector order)`, so `records`/`pixel_records` are identical to the `workers=1` (default) sequential path regardless of `workers`

### Changed

- `BaseDetector.predict` now takes `ForensicImage`
- `imgforensics.eval.metrics`: image-level threshold metrics (`accuracy_at_threshold`, `tpr_at_threshold`, `fpr_at_threshold`, `balanced_accuracy_at_threshold`, `best_threshold`) now predict "fake" only when `score > threshold` (strict), not `score >= threshold`, so a detector abstaining at exactly the default 0.5 operating point is no longer scored as calling every image fake; pixel-level metrics are unchanged and keep `>=` on heatmaps
- `imgforensics.detectors.features`: `FeatureExtractor.features_for_paths()` yields `(path, view, features)` instead of `(path, features)`, and `cache_hits` counts image-view pairs rather than images; `extract_to_cache()`'s summary gains `views` and `arrays`
- `imgforensics.eval.baselines`: the `signals_mean` baseline and the benchmark runner's `--all-signals` now iterate `imgforensics.signals.SIGNAL_NAMES` rather than the whole registry, so the signals floor a learned detector is measured against does not quietly absorb the learned detector itself once the `ml` extra registers one
- `imgforensics.detectors.crops`: `crops_for()` places its crops itself instead of delegating to `imgforensics.eval.preprocess`'s `center_crop`/`random_crops`, so `crop_boxes()` can report the same rectangles; the results are pixel-identical and a test pins that they stay so
